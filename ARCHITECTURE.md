## 1. Architectural Philosophy ("Zero-Breakage by Design")

AuraClean is engineered around a strict invariant: **safety recovery code and immutable barriers are enforced before any deletion or system modification code can execute.**

1. **No Blind Deletions:** Every cleanup operation is a reversible transaction recorded in a local SQLite index (`index.db`) and backed by a Tiered Quarantine policy.
2. **Least Privilege Execution:** The graphical frontend runs as a standard user process (`auraclean-ui.exe`). Administrative privileges are isolated to `auraclean-service.exe` over a hardened Named Pipe channel.
3. **Never Trust Arbitrary IPC Paths:** The elevated service never accepts raw file or registry deletion paths from the client. It only executes actions against validated `RuleId` and signed `ScanFindingId` tokens generated by its own scan engine.

## 4. Deep-Dive Technical Subsystems & Audit Fixes

### 4.1. Defense-in-Depth Safety Guard (`crates/safety-guard`)

1. **Compile-Time Immutable Whitelist (`whitelist.rs`):**
   * Hardcoded case-insensitive canonical prefix protection for:
     * `C:\Windows\WinSxS`
     * `C:\Windows\System32\config`
     * `C:\Windows\System32\DriverStore`
     * `C:\Windows\System32\catroot` & `catroot2`
     * `C:\Windows\Boot` & `C:\EFI`
   * Blocks deletion of critical system extensions (`.sys`, `.drv`, `.efi`, `.cat`) and protects `.dll` / `.exe` files outside explicitly designated cache/build directories.
   * Always prefixes paths with extended-length `\\?\` when exceeding `MAX_PATH` (260 characters) and rejects reparse points / symlinks (`FILE_ATTRIBUTE_REPARSE_POINT`) during recursive traversal to prevent symlink-escape attacks.

2. **Cloud Placeholder / Recall Guard (`cloud_guard.rs`):**
   * Before opening any file for inspection or hashing, AuraClean checks Win32 file attributes:
     * `FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS` (`0x00400000`)
     * `FILE_ATTRIBUTE_RECALL_ON_OPEN` (`0x00040000`)
     * `FILE_ATTRIBUTE_OFFLINE` (`0x00001000`)
     * `FILE_ATTRIBUTE_PINNED` / `FILE_ATTRIBUTE_UNPINNED`
   * Any unpinned cloud placeholder (OneDrive, iCloud Drive, Dropbox) is skipped immediately so AuraClean never triggers unwanted multi-gigabyte cloud downloads.

3. **24-Hour File Age & Boot Session Guard (`age_guard.rs`):**
   * Files in temporary directories modified or created within the configurable safety window (default `24 hours`) are automatically shielded so active MSI installers, compilers, or document auto-saves are never disrupted.

4. **Win32 Restart Manager & Exclusive Handle Inspection (`lock_detector.rs`):**
   * Uses `RmStartSession`, `RmRegisterResources` (in batches of up to 256 paths per API call for high throughput), and `RmGetList` from `windows::Win32::System::RestartManager`.
   * Supplements Restart Manager with a fast kernel sharing probe: `CreateFileW` with `dwDesiredAccess = GENERIC_READ | GENERIC_WRITE` and `dwShareMode = 0`. If `ERROR_SHARING_VIOLATION` (`32`) or `ERROR_LOCK_VIOLATION` (`33`) is returned, the file is marked `LockedByProcess` and skipped without error.

5. **Tiered Time-Capsule Quarantine & Quota Guard (`quarantine.rs`):**
   * **Problem Solved:** Archiving 30 GB of `target/` or shader caches into `C:\ProgramData\AuraClean\Vault` would exhaust a low-space system drive.
   * **Tier 1 — Full Zstandard Vault (`ArchiveToVault`):** Used for configurations, orphaned `AppData`, registry snapshots (`.reg` + JSON), and small/medium temporary files. Stream-compressed via `zstd` (level 3) into `vault_{tx_uuid}.tar.zst` with SHA-256 integrity hashes recorded in SQLite (`index.db`).
   * **Tier 2 — Reproducible Build & Cache Manifest (`ManifestOnly` / `FastRecycle`):** Used for massive reproducible artifacts (`node_modules`, Cargo `target/`, shader caches) or when single items exceed the per-item archive threshold. Records a reconstruction manifest (`Cargo.lock`/`package.json` metadata and rebuild command) in the transaction log without duplicating 20 GB on disk.
   * **Disk Quota Guard:** Enforces a configurable maximum Vault size (default `4 GB` and requires at least `5 GB` of free disk space remaining on the target volume). Automatic expiration purges archives older than 7 days.

6. **System Restore (VSS) Awareness:**
   * Checks whether Windows System Protection is enabled on the system drive and respects Windows 10/11's 24-hour `SystemRestorePointCreationFrequency` throttle, reporting accurate status to the user instead of silently failing.

### 4.2. Dual-Engine Disk Scanner (`crates/core-engine`)

1. **NTFS `$MFT` Direct Record Parser (Elevated Mode):**
   * Unlike `FSCTL_ENUM_USN_DATA` (which omits file sizes), AuraClean's elevated MFT scanner reads `$MFT` records directly (`$STANDARD_INFORMATION` + `$DATA` attribute headers) to construct the complete directory tree with exact physical/logical sizes in ~1.2 seconds.
2. **Automatic `jwalk` + `rayon` Fallback (User Mode & ReFS/exFAT):**
   * Automatically detects volume filesystem type via `GetVolumeInformationW`. On **ReFS (Windows 11 Dev Drive)**, **exFAT**, or when running without elevation in User Mode, seamlessly switches to parallel `jwalk` scanning with `follow_links(false)`.
3. **Signed TOML Rule Engine:**
   * Rules in `rules/*.toml` are validated against path-traversal sandboxes (rejecting root wildcards such as `C:\*` or `%USERPROFILE%\*`) and support Ed25519 signature verification (`ed25519-dalek`) for over-the-air rule updates.

---

### 4.3. Privilege Separation & Hardened IPC (`crates/ipc-protocol` & `crates/elevated-service`)

1. **Named Pipe Security Descriptor (SDDL):**
   * Pipe `\\.\pipe\AuraCleanPrivilegedService` is created with `FILE_PIPE_REJECT_REMOTE_CLIENTS` and an explicit DACL granting access only to `SY` (SYSTEM), `BA` (Built-in Administrators), and `AU` (Authenticated Local Users).
2. **Client Process Verification:**
   * Upon connection, the service retrieves the client PID via `GetNamedPipeClientProcessId`, resolves its image path via `QueryFullProcessImageNameW`, and verifies the Authenticode signature (`WinVerifyTrust`) in release builds.
3. **Explicit User SID Context (`UserContext`):**
   * Because a Windows Service runs in `Session 0` under `NT AUTHORITY\SYSTEM`, expanding `%APPDATA%` or opening `HKCU` inside the service would point to the `SYSTEM` profile instead of the logged-in user.
   * Every IPC request carries the caller's validated `UserContext` (`user_sid`, `user_profile_dir`, `local_appdata_dir`, `roaming_appdata_dir`, `preferred_locale`), and registry operations explicitly target `HKEY_USERS\<User-SID>\...`.
4. **Memory Footprint Optimization in Tray Mode:**
   * When the user closes the main window while **Ghost Hunter** remains active, Tauri destroys the `msedgewebview2.exe` view (`window.destroy()`) and retains only the native Rust tray loop (< 6 MB RAM). Clicking the tray icon re-instantiates the window in < 150 ms.

### 4.4. Specialized Modules

* **Multi-Drive Game Library Resolver:** Parses `steamapps/libraryfolders.vdf`, Epic Games `LauncherInstalled.dat`, and GOG/EA registry keys across all drives (`C:\`, `D:\`, `E:\`) before flagging any `AppData` folder as an orphaned game leftover. Always marks SaveGame patterns as `Protected`.
* **Standby Memory Purger:** Enables `SeProfileSingleProcessPrivilege` via `AdjustTokenPrivileges` before invoking `NtSetSystemInformation(SystemMemoryListInformation, MemoryPurgeStandbyList)`.
* **WOW64 Explicit Registry Inspection:** Compiled natively for 64-bit (`x86_64` / `aarch64`) and inspects both `KEY_WOW64_64KEY` and `KEY_WOW64_32KEY` views explicitly, while checking `GetDriveTypeW` so unmounted USB/network drives are never treated as broken registry paths.
